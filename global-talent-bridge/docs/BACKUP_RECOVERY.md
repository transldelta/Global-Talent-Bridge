# Backup & Recovery — CorridorWork

> **Scope:** This document covers automated backup strategy, manual export procedures, point-in-time recovery, and disaster-recovery playbook for the GTB production database (Supabase, eu-central-1).

---

## 1. Automated Backups (Supabase)

### Supabase Daily Backups
| Tier       | Backup Frequency | Retention | PITR  |
|------------|-----------------|-----------|-------|
| Free       | Daily           | 7 days    | ❌    |
| Pro        | Daily           | 7 days    | ✅ 7 days  |
| Team       | Daily           | 14 days   | ✅ 14 days |
| Enterprise | Custom          | Custom    | ✅ 30 days |

**Current tier:** Free/Pro (check Supabase dashboard → Settings → Billing)

### What is backed up automatically:
- All PostgreSQL tables (schema + data)
- Row-Level Security policies
- Functions, triggers, indexes
- Auth configuration (users, settings)
- Storage buckets metadata

### What is NOT backed up automatically:
- Storage bucket contents (files/images) — must be backed up separately
- Edge Function source code (stored in repo, not DB)
- Environment variables / secrets (stored in Vercel + Supabase, not in repo)

## 2. Manual Export Procedures

### 2a. Full Database Export via Supabase CLI
```bash
# Requires supabase CLI + project linked
supabase db dump -f backup_$(date +%Y%m%d).sql --linked

# Export only data (no schema):
supabase db dump -f data_$(date +%Y%m%d).sql --linked --data-only

# Export specific tables:
supabase db dump -f corridors_$(date +%Y%m%d).sql --linked --table corridors --table migration_intelligence
```

### 2b. Export via Supabase Dashboard
1. Go to **supabase.com/dashboard/project/qjxojvxhsoicldccfmkq**
2. Navigate to **Database → Backups**
3. Click **Download** on the desired daily snapshot
4. Unzip the `.tar.gz` and restore with `psql`

### 2c. Table-Level JSON Export (via Admin API)
Each major table has an admin API GET endpoint that returns JSON:
```bash
# Example: export corridors
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  https://your-domain/api/admin/global/corridors \
  > corridors_export.json

# Export Migration Intelligence data
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  https://your-domain/api/admin/global/migration-intelligence \
  > mi_export.json
```

## 4. Point-in-Time Recovery (PITR)

> Requires Supabase **Pro** tier or higher.

### How to restore to a specific timestamp:
1. Go to **supabase.com/dashboard/project/qjxojvxhsoicldccfmkq**
2. Navigate to **Database → Backups → Point in Time**
3. Select the recovery timestamp (UTC)
4. Click **Restore** — this creates a new branch or overwrites current
5. Verify all tables and RLS policies are intact
6. Re-apply any migrations created after the recovery point

### PITR Coverage:
- WAL (Write-Ahead Log) is captured every **2 minutes**
- Maximum granularity: ~2-minute windows
- Retention: 7 days (Pro), 14 days (Team)

## 6. Disaster Recovery Playbook

### Scenario A: Database Corrupted / Accidental Mass Delete
1. **Stop all agents** — disable cron jobs / webhook triggers
2. **Assess damage** — check `system_logs` for what happened
3. **Restore from daily backup** (Supabase Dashboard → Backups)
4. **Or use PITR** to pinpoint exact timestamp before corruption
5. **Re-apply migrations** if schema was dropped
6. **Re-seed critical tables** if data was lost (corridors, revenue_plans)
7. **Restart agents** — run orchestrator once to recompute scores
8. **Verify** — check system-health and system-audit dashboards

### Scenario B: Vercel Deployment Broken
1. Go to **Vercel Dashboard → Deployments**
2. Find last working deployment
3. Click **Promote to Production** to rollback
4. Check environment variables are intact

### Scenario C: Supabase Project Deleted
1. Create new Supabase project (eu-central-1)
2. Update `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` + `SUPABASE_SERVICE_ROLE_KEY` in Vercel
3. Apply all migrations from `supabase/migrations/`
4. Restore data from SQL dump or CSV exports
5. Re-configure Auth providers (Google, etc.) if applicable
6. Update `ADMIN_EMAILS` env var

### Scenario D: Secrets Leaked
1. Immediately rotate in Supabase Dashboard (Settings → API → Regenerate)
2. Update all affected env vars in Vercel
3. Audit `system_logs` for unauthorized agent runs
4. Create a `system_incidents` entry documenting the event
5. Review RLS policies — ensure no public write access exists
